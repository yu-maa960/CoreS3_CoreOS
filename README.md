# CoreOS for M5Stack CoreS3

## 概要
ESP32-S3(M5Stack CoreS3)の豊富なハードウェア機能を統合管理するためにゼロから設計した，軽量なイベント駆動型OSおよびUIフレームワークです．
単一の`loop()`に依存する組込みコードから脱却し，高い保守性と拡張性を持つアーキテクチャーを実装しました．

## 使用技術
* **言語**: C++(C++17)
* **環境**: PlatformIO / VS Code
* **ハードウェア**: M5Stack CoreS3(ESP32-S3)
* **ライブラリ**: M5Unified, M5GFX
* **設計手法**: オブジェクト指向設計(Factory Method パターン，継承，ポリモーフィズム)，イベント駆動アーキテクチャ

## 機能一覧

* **OS / UI コア基盤**
  * イベントキューを用いたメッセージングとタスク実行
  * Factoryパターンを用いたアプリケーションの動的生成・破棄
  * ダブルバッファリング(`Sprite`)によるフリッカーフリーなUI描画

* **アプリケーション**
  * **ENV Logger**
    * 温湿度・気圧センサ(I2C)からのリアルタイムデータ取得とUI描画
    * SDカードへの測定データのログ保存
  * **Camera Viewer**
    * 内蔵カメラによるリアルタイム映像プレビュー表示
    * ワンタップでの静止画キャプチャおよびSDカードへの書き込み保存
  * **Audio Player**
    * WAVE形式専用のイントロ再生からメインループへのシームレス無限再生
    * PSRAM(8MB)容量を考慮し，ループ部を優先確保する動的メモリ管理
  * **SD Manager**
    * SDカード内ファイル一覧のリスト表示およびタッチ選択インターフェース
    * 拡張子判別(jpg / wav)による画像プレビュー表示と音声再生連携

## 工夫した点・苦労した点と解決策

### 1. ハードウェア競合の特定と低レイヤーデバッグ
* **I2C(Wire1)の二重初期化によるフリーズ**
  * **課題**: カメラライブラリを初期化した際，システム全体が完全停止する問題が発生．
  * **原因**: ライブラリ内部でI2C(Wire1)を新規初期化しようとした結果，CoreS3起動時にすでに電源管理IC等と確立されていた既存通信路と衝突し，電源制御が切断されていた．
  * **解決策**: ライブラリの新規初期化を無効化し，起動済みの通信路(Wire1)を共有させる設定に変更して回避．
* **カメラとSDカードの物理ピン競合**
  * **課題**: デフォルトの `SD.begin()` を呼ぶと，カメラかSDカードのどちらか片方が動作不能になりクラッシュした．
  * **原因**: ESP32標準のSDピンが，CoreS3の基板上ではカメラのデータ線として配線されていたため信号衝突が発生．
  * **解決策**: 回路図とピンマップを精査し，CoreS3固有の正しいピン番号(36, 35, 37, 4番)をコード上で明示的に指定して初期化することで同時利用を実現．

### 2. 保守できる設計へのリファクタリング
* **巨大な `loop()` の解体とレイヤー分離**
  * **課題**: 初期実装時は画面判定・ハード制御・アプリ処理が1つの `loop()` に混在し，機能を追加するたびにコードが肥大化・複雑化して保守が困難になった．
  * **解決策**: 単に動かすだけでなく持続的に開発できる構造を目指し，システムを「Application層」「OS層」「HAL(ハードウェア抽象化)層」に再構築．ハードウェアを直接叩く処理をHALに隔離したことで，各アプリは純粋なロジックと画面描画のみに集中できるようになり，コードの見通しが劇的に改善．
* **イベント駆動とFactoryパターンによる疎結合化**
  * **工夫点**: 抽象的な要求データ(構造体)をキューに投げるイベント駆動モデルを採用．アプリ生成を担うFactoryクラスを介し，OS側は基底クラスのポインタ(`AppBase*`)のみを扱うことで，OSと各アプリの依存関係を最小限に抑制．
* **OSによるPSRAM動的メモリ管理**
  * **工夫点**: 各アプリが野良でヒープを確保してメモリを無秩序に消費するのを防ぐため，メモリ割り当て権限をOSに集約．
  * **実装**: 音楽ファイル読み込み時など，大容量バッファが必要な際はアプリが必要サイズを引数でOSへ要求．OSがPSRAMから一元的に領域を確保してポインタを即時(キューを介さず同期的)に返却し，使用後はOSへ返還するライフサイクルを構築．
  * 
### 3. 限られたメモリリソース(RAM / PSRAM)の最適化
* **char配列の事前確保・使い回しとポインタ活用**
  * **工夫点**: ヒープの断片化やコピーのオーバーヘッドを避けるため，`String` クラスは一切使用せず．必要なバッファをchar配列として事前に確保して使い回す，またはcharのポインタ型で定義することで，メモリ消費を最小限に抑制．
* **PSRAM容量を意識した動的バッファリング(BGM再生)**
  * **課題**: 8MBのPSRAMに対して，大容量のWAVE音源(イントロ＋メインループ)を無計画に読み込むとメモリ枯渇によるパニックを引き起こすリスクが存在した．
  * **解決策**: 音途切れが許されないメインループ部分を最優先でメモリに確保し，残りの空き容量を計算．イントロ部が収まる場合のみロードを行う優先度制御ロジックを実装し，安全性を担保．

## 実行方法

### 動作前提環境(事前準備)
* **ハードウェア**: M5Stack CoreS3 本体，USB Type-C ケーブル
* **開発環境**: [Visual Studio Code](https://code.visualstudio.com/)
* **VS Code 拡張機能**

### 1. リポジトリのクローン
ターミナルを開き，本リポジトリをクローンして作業ディレクトリへ移動します．

```bash
git clone https://github.com/yu-maa960/CoreS3_CoreOS.git
cd CoreS3_CoreOS
```

### 2. 環境設定
`src/Common/Secrets.h` を開き，お使いのWi-Fi環境のSSIDおよびパスワードを設定してください．

```cpp
namespace Secrets {
    constexpr const char* WIFI_SSID     = "YOUR_SSID";
    constexpr const char* WIFI_PASSWORD = "YOUR_PASSWORD";
}
```

### 3. ビルド & 実機への書き込み
M5Stack CoreS3をPCにUSB接続し，以下のいずれかの方法でビルドとファームウェアの書き込みを実行します．

* **VS Code(GUI)から実行する場合:**  
  画面下部ステータスバーの **PlatformIO: Upload(→ アイコン)** をクリック．
* **ターミナル(CLI)から実行する場合:**  
  ```bash
  pio run -t upload
  ```
